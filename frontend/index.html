    Understanding Hashing

    What is Hashing?
    • A one-way transformation: practical to compute, impractical to reverse.
    • Produces a fixed-length digest regardless of input size.
    • The same input always produces the same output.
    • A small change to the input produces a completely different digest (the avalanche effect).
    • Practically irreversible — you cannot recover the original input from the digest alone.
    Hashing vs Encryption vs Encoding

    Hashing is one-way and produces a fixed-length digest used for verification — it cannot be reversed.

    Encryption is two-way: data is transformed with a key and can be decrypted back to the original with the correct key.

    Encoding (Base64, Hex, URL, ROT13) is a reversible format transformation with no security purpose — anyone can decode it without a key.

    Why Hashes Are Used
    • File integrity verification
    • Duplicate detection
    • Password verification (with proper salting/KDFs)
    • Digital signatures
    • Blockchain data structures
    Common Algorithms
    MD5SHA1SHA-2 SHA-3BLAKE2bcrypt scryptArgon2

    MD5 and SHA1 are fast but considered broken for security-critical use due to collision attacks — they still work fine for non-security checksums. The SHA-2 family (SHA224/256/384/512) and SHA-3 family are today's standards for integrity and digital signatures. BLAKE2 offers SHA-3-level security with better speed. For passwords specifically, dedicated slow algorithms like bcrypt, scrypt, or Argon2 should be used instead of general-purpose hash functions.

    Real-World Examples
    • Software checksum verification for downloads
    • Git's content-addressed object storage
    • Digital forensics and evidence-integrity chains
    Best Practices
    • Do not use raw MD5/SHA1 for password storage.
    • Use salted password hashing / key-derivation functions (bcrypt, scrypt, Argon2).
    • Prefer SHA-256 or stronger for integrity verification.
    • Use constant-time comparison in security-sensitive applications.
